# MAHA SALES ENGINE V1 - Product Package Specification

## Overview

This document defines the exact structure and requirements for every product package generated by the Product Factory.

## Package Structure

Every product package MUST follow this exact structure:

```
{PRODUCT_ID}/
├── metadata.json          # REQUIRED: Product metadata
├── description.md         # REQUIRED: Product description
├── license.txt            # REQUIRED: License terms
├── keywords.json          # REQUIRED: SEO keywords
├── pricing.json           # REQUIRED: Pricing information
├── version.json           # REQUIRED: Version information
├── history.json           # REQUIRED: Change history
├── quality_report.json    # REQUIRED: Quality check results
├── product/               # REQUIRED: Product content
│   └── [content files]
├── preview/               # REQUIRED: Preview assets
│   └── [preview files]
└── thumbnail/             # REQUIRED: Thumbnail images
    └── [thumbnail files]
```

## File Specifications

### metadata.json

```json
{
  "product_id": "ML-20260727-000001",
  "title": "Product Title",
  "description": "Product description",
  "category": "ebook",
  "version": "1.0.0",
  "author": "MAHA LAKSHMI",
  "license": "commercial",
  "language": "en",
  "tags": ["tag1", "tag2"],
  "target_market": "global",
  "price_usd": 29.0,
  "price_idr": 435000,
  "created_at": "2026-07-27T00:00:00",
  "updated_at": "2026-07-27T00:00:00",
  "file_count": 10,
  "total_size_bytes": 15360
}
```

**Required fields:**
- product_id: Globally unique ID
- title: Product title
- description: Short description
- category: Product category
- version: Semantic version
- author: Author name
- license: License type

### description.md

Markdown file with:
- Product title as H1
- Product description
- Features list
- What's included section

### license.txt

Plain text license terms based on license type:
- Personal
- Commercial
- Extended
- Custom

### keywords.json

```json
{
  "keywords": ["keyword1", "keyword2", ...],
  "primary_keywords": ["keyword1", "keyword2", "keyword3"],
  "secondary_keywords": ["keyword4", "keyword5", ...],
  "long_tail_keywords": ["long tail keyword1", ...]
}
```

## Quality Standards

### Minimum Requirements
- All required files present
- All JSON files valid
- Metadata completeness: 100%
- Minimum content size: 1KB
- Quality score: >= 80%

### File Naming
- Use snake_case for filenames
- No spaces in filenames
- Descriptive names
- Include product ID where appropriate

## Product Content by Type

### eBook
- PDF source (Markdown)
- Minimum 5 chapters
- Table of contents
- Conclusion
- Resources section

### Template
- Template files (HTML, Excel, Canva)
- Usage instructions
- Preview assets

### Prompt Pack
- prompts.json
- README.md
- Category tags

### Checklist
- checklist.json
- checklist.md
- Minimum 5 items

### Mini Course
- course_structure.json
- Module directories
- Lesson files

## Validation Rules

1. **File Presence**: All required files must exist
2. **JSON Validity**: All JSON files must be valid
3. **Metadata Completeness**: All required fields present
4. **Content Size**: Minimum 1KB total
5. **Naming Standards**: No spaces, snake_case
6. **Folder Structure**: Exact structure required
7. **License**: License file must exist
8. **Description**: Description file must exist
9. **Preview Assets**: Preview and thumbnail directories must exist

## Version History

Every version includes:
- Version number (semantic)
- Timestamp
- Author
- Changelog
- File hash
- File size

## Rollback Support

Any version can be rolled back to:
1. Backup current version
2. Restore files from version directory
3. Update version history
4. Log rollback action
